# 南陵麻将 · 胡牌规则实现说明

> 依据《南陵麻将·胡牌成牌规则精解》（7 页 PPT）整理，并结合代码实现标注口径。

## 一、三层判定模型

任何一手牌都按固定顺序自检，**三层全过才算胡**：

```
① 基础牌型（硬前提） → ② 缺一门（花色约束） → ③ 调味剂（胡牌条件）
```

1. **基础牌型**：14 张 = 4 副面子 + 1 对将牌。
   - 面子可为顺子或刻子，每副固定 3 张；杠按一副面子计算。
   - 结构不成，其余规则再满足也不能胡。
2. **缺一门**：万、筒、条三色必须至少少一门。
   - 字牌（东南西北中发白）不计入花色，不影响缺一门判定。
3. **调味剂**：手牌含癞子时，必须命中 `9支` / `11支` / `混一色` / `跑风` 之一。
   - 无癞子手牌可裸胡（无癞子单钓），不要求任何调味剂。

## 二、关键概念口径

| 概念 | 判定口径 | 代码位置 |
| --- | --- | --- |
| 9支 | 同一花色「实牌 + 癞子」合计 **超过 9 张**（≥10） | `WinChecker#evaluate` |
| 11支 | 同一花色合计 **超过 10 张**（≥11） | 同上 |
| 癞子凑整 | 实牌 + 癞子刚好 9 张 **不算** 9支 | 同上（严格大于） |
| 混一色 | 只有一门序数牌（万/筒/条）+ 字牌 | 同上 |
| 清一色 | 14 张全在同一门序数牌，无字牌 | 同上 |
| 跑风 | 癞子充当**将头对子**时触发；癞子作顺子/刻子不计 | `Decomposition.pairUsedJoker` |
| 杠 | 每杠计 1 番，杠的 4 张牌计入花色张数 | `MeldType#isKong` |
| 无癞子单钓 | 手牌无癞子，结构成立 + 缺一门即可胡 | `needsFlavor = false` |
| 只能自摸 | 南陵麻将**不允许胡别人打出的牌**，没有点炮、没有一炮多响 | `GameTable#claimsForTile` 不返回 HU |

> 口径来源：PPT 第 7 页「易错一 / 易错二 / 补充说明」。
> 易错一：癞子参与凑出刚好 9 张不算 9 支，须是实牌加癞子合计超过 9 张。
> 易错二：癞子仅当充当将头对子时才触发跑风，作顺子或刻子使用不计跑风。

## 四、算分（对齐《芜湖麻将-南陵》PDF）

### 4.1 牌型分（加法累加）

| 项目 | 分值 | 说明 |
| --- | --- | --- |
| 基础（开牌） | **+1** | 任何一手成立的牌都有，和 9支 互为因果 |
| 9支 | 0 | 本身不计分，它是「开牌 +1」的由来 |
| 11支 | +3 | 与 9支 叠加 |
| 混一色 | +2 | 与清一色互斥 |
| 清一色 | +4 | 与混一色互斥 |
| 跑风 | +1 | 将牌里含癞子 |
| 单钓 | +1 | 胡的那张就是将牌 |
| 杠 | +1 / 个 | 明杠暗杠同价，多个累加 |
| 杠开 | +2 | 杠后补牌直接自摸，与杠分叠加 |

示例：纯 9支 = 1；9支 + 11支 = 4；混一色 + 单钓 = 4；清一色 + 跑风 + 11支 = 8。

### 4.2 底分与欢乐豆

- **底分**由房主在创建房间时（或开局前在房间页）设置，取值 1~10，默认 1。
- **单家应付 = 牌型分 × 底分**。
- 每人开局 **20 豆**（`mahjong.game.start-beans`）。
- **只能自摸**，所以是三家付：赢家 `+3 × 单家应付`，另外每家 `-单家应付`。
- **头家 ±1**（按 PDF）：头家胡牌多 +1；头家输牌多扣 1，其他玩家不受影响。
  > 注意：这条是 PDF 原文「其他玩家不受影响」，因此当非头家自摸时，
  > 全场欢乐豆总量会少 1 豆。这是规则本身的口径，不是 bug。

举例（底分 1，头家没胡）：牌型分 5 → 单家 5 豆 → 赢家 +15，头家 -6，另外两家各 -5。

> 分值集中在 `Flavor` 枚举，结算是 `BeanSettlement.deltaFor(...)`，同一套算术
> 同时给「落库结算」和「前端弹窗的增减」用，不会出现弹窗和余额对不上。

## 五、延时申请（三家同意才生效）

轮到自己出牌（或等着自己响应）时可以点「延时」：

1. 当前剩余时间被**冻结**，进入 **60 秒**投票窗口；
2. 其他三家各自投「同意 / 不同意」；
3. 三家全同意 → `剩余时间 = 冻结时间 + 一个基础时长`（出牌看 turn-timeout，响应看 action-timeout）；
4. 任意一家不同意 → 原样还回冻结的时间，申请人不会因为发起投票白赚时间；
5. 出牌、超时、本局结束都会清掉申请。

单人房里的机器人会逐个投同意（一个 tick 一票），不会卡住投票。

## 六、自制规则：打出癞子，全场作废

**默认关闭**，由房主在房间页手动开启（协议 `ROOM_RULE`）。开启后：

> 本局只要有人**打出**癞子，则所有玩家手上的癞子都不再是万能牌，
> 只能按它本身的牌面参与胡牌判定。一局内一旦触发不可恢复。

实现要点：`RuleConfig.voidWildcardOnDiscard` 存开关，`GameTable.wildcardVoided` 存本局是否已触发。

| 方面 | 触发前 | 触发后 |
| --- | --- | --- |
| 补顺子 / 刻子 | 癞子可当任意牌 | 只能用自身牌面，补不上就组不成面子 |
| 作将（跑风） | 癞子 + 实牌可作将，并计跑风 | 跑风失效，癞子只能当自身牌面的实牌 |
| 9支 / 11支 | 实牌 + 癞子合计 | 只数真实牌面（癞子按自身花色计入） |
| 调味剂要求 | 手牌含癞子必须命中调味剂 | 等于手里没有癞子，可裸胡 |

判定入口在 `WinChecker`：作废时不再把癞子抽进 `jokers`，而是直接计入 `counts`，
后续拆解与算番逻辑完全复用，不需要单独分支。

口径约定：只有「**打出**」触发；碰、明杠、暗杠、补杠都不触发。

## 七、暂未覆盖的规则（需确认）

以下条目 PPT 未涉及，当前版本**未实现**，已在代码中留出扩展点：

1. **抢杠胡**：补杠时其他玩家可否胡这张牌。
2. **一炮多响**：南陵麻将不能胡别人打出的牌，此条不再适用。
3. **杠上开花 / 杠上炮**：杠后补牌自摸的额外番（杠开 +2 已实现，杠上炮不适用）。
4. **海底捞月**：牌墙最后一张自摸。
5. **癞子确定方式**：当前实现「翻宝 → 取同花色后一张」（`WildcardMode.FLIP_NEXT`），也支持房主指定固定癞子。
6. **字牌是否计入 9支**：当前只统计万/筒/条。
7. **七对、十三烂等特殊牌型**：当前不支持。
8. **吃**：南陵麻将不吃，已从动作集合中移除。

## 八、判定伪代码

```
check(hand, melds, config):
  if 手牌张数 != 14 - 3 * 面子数: 失败
  把癞子从手牌中剥离，得到 counts[34] 和 jokers
  for 每种将牌 p:
     尝试「两张实牌」「一实一癞（跑风）」「两张癞子」作将
     递归拆解剩余牌为 4 - 面子数 副面子（顺子/刻子，缺的用癞子补）
  收集所有合法拆解
  if 无拆解: 失败（牌型不成立）
  for 每种拆解:
     把癞子解析成具体牌面 → 统计花色
     if 三色俱全: 跳过（缺一门不满足）
     if 手牌含癞子 and 未命中 9支/11支/混一色/跑风: 跳过
     计算番型，取番数最高的拆解
  返回最高番结果
```

> 之所以要「把癞子解析成具体牌面再统计」，是因为规则要求「实牌 + 癞子合计超过 9 张」，
> 直接按手牌原始张数统计会把「癞子凑整 9 张」误判为 9支。
