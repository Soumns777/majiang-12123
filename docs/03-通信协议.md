# 通信协议

- 地址：`ws://<host>:8080/ws/game`（上线换 `wss://`）
- 编码：UTF-8 JSON 文本帧
- 信封：`{ "type": "消息类型", "data": { ... } }`
- 牌编码：`1W`~`9W` 万、`1T`~`9T` 筒、`1B`~`9B` 条、`E/S/W/N/C/F/P` 东南西北中发白

## 一、客户端 → 服务端

| type | data | 说明 |
| --- | --- | --- |
| `HELLO` | `{playerId?, nickname, avatar?}` | 建立身份。`playerId` 留空则新建；带上原 id 可断线重连 |
| `ROOM_CREATE` | `{baseScore?, maxRounds?, wildcardMode?, wildcardTile?}` | 创建房间，房主自动入座 0 号位 |
| `ROOM_JOIN` | `{roomId}` | 加入房间。有空位就坐下；**满员或已开局时自动降级为观战**，不再报错 |
| `ROOM_WATCH` | `{roomId}` | 主动观战。不论满没满、开没开局，都只观战不占座 |
| `ROOM_LEAVE` | `{}` | 退出房间。玩家在对局中不可退出，观战者随时可退 |
| `ROOM_READY` | `{ready: boolean}` | 准备 / 取消准备 |
| `ROOM_RULE` | `{voidWildcardOnDiscard?: boolean, baseScore?: number}` | 房间内改规则。`baseScore` 底分 1~10；仅房主、仅 `WAITING` 阶段可改，两个字段可只带一个 |
| `ROOM_BOT` | `{count?: number}` | 房主往空座位补机器人，默认 3 个。机器人自动在线 + 已准备，一个人也能开局 |
| `GAME_START` | `{}` | 房主开局，需 4 人且全部准备 |
| `GAME_ACTION` | `{action, tile?}` | 对局动作，见下表 |
| `GAME_EXTEND` | `{}` = 申请延时；`{agree: boolean}` = 投票 | 延时申请与投票，见「延时」一节 |
| `NEXT_ROUND` | `{}` | 房主开始下一局 |
| `PING` | `{}` | 心跳 |

### GAME_ACTION 的 action

| action | 需要 tile | 场景 |
| --- | --- | --- |
| `DISCARD` | 是 | 轮到自己出牌 |
| `PONG` | 否 | 响应别人打出的牌 |
| `KONG_MING` | 否 | 直杠（手牌 3 张 + 别人打出的 1 张） |
| `KONG_AN` | 是 | 暗杠（手上 4 张） |
| `KONG_BU` | 是 | 补杠（碰后摸到第 4 张） |
| `HU` | 否 | **只能自摸**；在 `WAITING_CLAIM` 阶段发 HU 会报错「南陵麻将不能胡别人打出的牌，只能自摸」 |
| `PASS` | 否 | 放弃响应 |

## 二、服务端 → 客户端

| type | data | 说明 |
| --- | --- | --- |
| `HELLO_ACK` | `{playerId, nickname, avatar}` | 身份确认，客户端需存下 `playerId` |
| `ROOM_STATE` | `TableView` | 全量牌桌视图（**每人一份，手牌互相不可见**） |
| `LEFT` | `{roomId}` | 已退出房间 |
| `ERROR` | `{code, message}` | 操作失败 |
| `PONG` | `{}` | 心跳回包 |

> 服务端不推送增量事件，任何变化都推一份新的 `ROOM_STATE`，客户端整体替换即可。

```jsonc
{
  "roomId": "158220",
  "ownerId": "u_1001",
  "status": "PLAYING",          // WAITING | PLAYING | FINISHED
  "round": 1,
  "maxRounds": 8,
  "baseScore": 1,                // 底分：单家应付 = 牌型分 × 底分
  "phase": "PLAYER_TURN",       // WAITING | PLAYER_TURN | WAITING_CLAIM | ENDED
  "currentSeat": 0,
  "remainingTiles": 54,
  "wildcard": "5T",             // 癞子牌编码，可能缺省
  "wildcardLabel": "五筒",
  "voidWildcardOnDiscard": true, // 房间是否开启了「打出癞子，全场作废」
  "wildcardVoided": false,       // 本局癞子是否已作废（有人打出过癞子）
  "lastDiscardTile": "9B",      // 可能缺省
  "lastDiscardSeat": 2,
  "deadlineAt": 1762176000000,  // 当前阶段截止时间戳
  "serverTime": 1762175988000,  // 用于客户端校正时钟
  "spectator": false,           // 当前连接者是否为观战者
  "spectators": ["围观的老王"],  // 观战者昵称列表
  "extend": {                   // 延时申请，没有申请时该字段缺省
    "seat": 1,                  // 申请人座位
    "approvals": [2, 3],        // 已同意的座位（不含申请人）
    "need": 3                   // 需要几家同意
  },
  "players": [
    {
      "seat": 0,
      "playerId": "u_1001",
      "nickname": "东家",
      "avatar": "",
      "score": 0,
      "beans": 20,                    // 欢乐豆余额，开局 20
      "ready": true,
      "online": true,
      "bot": false,                   // 机器人：服务端定时器代打，sessionId 恒为空
      "dealer": true,
      "current": true,
      "handCount": 14,
      "hand": ["1W", "2W", "..."],   // 仅自己可见，别人为空数组
      "melds": [
        { "type": "PONG", "tiles": ["5W", "5W", "5W"], "fromSeat": 2, "exposed": true }
      ],
      "discards": ["9B"],
      "actions": ["HU", "DISCARD"]    // 仅自己可见，按优先级排序
    }
    // 其余 3 个座位结构相同；空位 playerId 为 ""
  ],
  "result": null
}
```

### 结算 result

```jsonc
{
  "drawGame": false,
  "winnerSeat": 3,
  "loserSeat": -1,             // 南陵麻将只能自摸，恒为 -1
  "fan": 6,                    // 牌型分合计
  "score": 12,                 // 单家应付欢乐豆 = fan × baseScore
  "baseScore": 2,
  "flavors": ["基础", "混一色", "9支", "11支"],
  "breakdown": [               // 胡了什么：逐项列给前端展示
    { "label": "基础", "fan": 1 },
    { "label": "混一色", "fan": 2 },
    { "label": "9支", "fan": 0 },
    { "label": "11支", "fan": 3 }
  ],
  "deltas": [                  // 四家欢乐豆增减，服务端算好直接下发
    { "seat": 0, "beans": -13 },  // 头家没胡：-12 再 -1
    { "seat": 1, "beans": -12 },
    { "seat": 2, "beans": -12 },
    { "seat": 3, "beans": 36 }    // 赢家 +3 × 12
  ],
  "winningHand": ["1W", "2W", "..."]   // 解析后的 14 张
}
```

> `deltas` 和落库结算共用 `BeanSettlement.deltaFor(...)`，所以弹窗的增减和余额永远对得上。

## 四、延时

`GAME_EXTEND` 一条消息两种用法：

| 发送 | 含义 |
| --- | --- |
| `{"type":"GAME_EXTEND","data":{}}` | 申请延时。只有「轮到自己出牌」或「等着自己响应」时允许，且同一时刻只能有一个申请 |
| `{"type":"GAME_EXTEND","data":{"agree":true}}` | 同意（`false` 为不同意）。申请人不能给自己投票 |

服务端行为：

1. 申请时把当前剩余时间**冻结**，`deadlineAt` 改成 60 秒投票窗口的截止时间；
2. 三家全同意 → `deadlineAt = now + 冻结时间 + 一个基础时长`；
3. 任意一家不同意 → `deadlineAt = now + 冻结时间`（申请人白等，但不亏）；
4. 出牌、超时、本局结束都会清掉申请，`extend` 字段随之消失；
5. 单人房里的机器人会逐个投同意（一个 tick 一票）。

## 五、观战

用房间号就能看别人打牌，两条路径：

| 入口 | 行为 |
| --- | --- |
| `ROOM_JOIN` | 有空位就坐下；**满员或已开局时自动转为观战**，不再返回「房间已满」 |
| `ROOM_WATCH` | 永远只观战，即使有空位也不占座 |

约束：

- 观战者**不进** `players` 列表，不占座位、没有准备态、不参与结算。
- 服务端按 `viewerId` 生成视图：观战者的 `spectator` 为 `true`，
  四个座位的 `hand` 全为空数组、`actions` 全为空，`handCount` 照常下发；
  暗杠的 `melds` 依然是 `exposed: false` 且 `tiles` 为空，观战者同样看不到牌面。
- 观战者发 `GAME_ACTION` 会被拒绝：`ERROR {message: "观战中不能进行牌局操作"}`。
- 观战者不受「对局中不能退出」限制，`ROOM_LEAVE` 随时生效。
- 单房间观战人数上限 20，超过返回 `ERROR {message: "观战人数已满"}`。

```
客户端（观战）                  服务端
  │  HELLO                        │
  │ ────────────────────────────▶ │
  │  ROOM_JOIN {roomId}（房间已满）│
  │ ────────────────────────────▶ │
  │  ROOM_STATE {spectator:true,  │
  │    players[].hand 全为空}     │
  │ ◀──────────────────────────── │
```

## 六、机器人代打

一个人也能开局：房主在 `WAITING` 阶段发 `ROOM_BOT {count}`，服务端把空座位填成机器人。

- 机器人是 `Player`，`bot: true`、`ready: true`、`online: true`、`sessionId: null`；
  广播时跳过它们，所以它们永远不会收到 `ROOM_STATE`。
- **依次出牌**：服务端每 300ms tick 一次，但一个 tick 只让「当前该动的那一位」做一个动作，
  动作完把 `botActAt` 推到 `now + mahjong.bot.think-ms`（默认 1100ms）。
  于是画面上是「上家打完 → 停一下 → 下家摸打」，不会一瞬间把整局牌打光。
- 真人的每次 `GAME_ACTION` 也会把 `botActAt` 往后推，机器人不会抢在真人后面立刻出牌。
- 决策见 `BotBrain`：能胡就胡 → 有概率碰 → 否则出「最没用」的牌（孤张字牌优先，癞子永远不打）。
- 机器人只在 `PLAYER_TURN`（轮到自己）和 `WAITING_CLAIM`（该自己响应）时动作，
  真人该出牌时牌桌保持不动，直到真人操作或超时。
- 真人全部离开后房间直接回收，不留下满桌机器人。

```
tick(300ms) ─┬─ 到点了吗？ ──否──▶ 什么都不做
             └─ 是 ──▶ 当前该动的座位是机器人？
                        ├─ 否 ──▶ 等真人（超时由 onTimeout 兜底）
                        └─ 是 ──▶ 执行一个动作 ──▶ botActAt += think-ms ──▶ 广播 ROOM_STATE
```

## 七、典型流程

```
客户端                          服务端
  │  HELLO                        │
  │ ────────────────────────────▶ │
  │  HELLO_ACK {playerId}         │
  │ ◀──────────────────────────── │
  │  ROOM_CREATE                  │
  │ ────────────────────────────▶ │
  │  ROOM_STATE {roomId, ...}     │
  │ ◀──────────────────────────── │
  │  ROOM_READY {ready:true}      │
  │ ────────────────────────────▶ │
  │  ROOM_STATE                   │
  │ ◀──────────────────────────── │
  │  GAME_START                   │
  │ ────────────────────────────▶ │
  │  ROOM_STATE {status:PLAYING}  │
  │ ◀──────────────────────────── │
  │  GAME_ACTION {DISCARD, 5W}    │

  │  ROOM_STATE（4 人各一份）      │
  │ ◀──────────────────────────── │
```

## 八、错误码

| code | 含义 |
| --- | --- |
| 4000 | 消息格式错误 |
| 4001 | 参数非法（未知操作、非法牌编码） |
| 4010 | 未发送 HELLO |
| 4011 | 未加入房间 |
| 4040 | 房间不存在或已解散 |
| 5000 | 服务器内部错误 |
| 5001 | 房间号分配失败 |

## 九、超时策略

| 阶段 | 默认超时 | 超时行为 |
| --- | --- | --- |
| `PLAYER_TURN` | 20s | 自动打出最后摸到的牌 |
| `WAITING_CLAIM` | 15s | 未响应的玩家自动视为「过」 |
| 延时投票 | 60s | 投票窗口结束仍未集齐三家同意，视为延时失败，恢复冻结前的剩余时间 |

客户端可用 `deadlineAt - (本地时间 + 时钟偏差)` 渲染倒计时，
时钟偏差 = `serverTime - 收到消息时的本地时间`。
