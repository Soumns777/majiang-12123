# 架构设计

## 一、总体结构

```
┌─────────────────────────────┐        WebSocket (JSON)        ┌──────────────────────────────┐
│  微信小程序 (Taro + React)   │  ───────────────────────────▶  │  Java 后端 (Spring Boot 3)    │
│  首页 / 房间 / 牌桌           │  ◀───────────────────────────  │  WS 接入 → 房间服务 → 对局引擎 │
└─────────────────────────────┘        个性化牌桌视图            └──────────────┬───────────────┘
                                                                                │
                                                                     RoomRepository（接口）
                                                                                │
                                                             ┌──────────────────┴─────────────────┐
                                                             │ InMemoryRoomRepository（当前）      │
                                                             │ JPA / MyBatis 实现（服务器到位后）   │
                                                             └────────────────────────────────────┘
```

**当前版本（feature-1.0.0）不接数据库**，房间、玩家、对局状态全部驻留内存，
进程重启即丢失。所有持久化动作都收敛在 `RoomRepository` 一个接口上，
服务器到位后新增实现并切换 `mahjong.storage.mode` 即可，业务代码不改。

## 二、技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 小程序 | Taro 4.0.9 + React 18 + TypeScript | 一套代码可编译 weapp / h5 |
| 状态管理 | Zustand | 轻量，无 Provider 嵌套 |
| 样式 | SCSS + rpx | 750 设计稿 |
| 后端 | Java 17 + Spring Boot 3.2.5 | Web + WebSocket |

| 存储 | 内存（`ConcurrentHashMap`） | 数据库后置 |

## 四、后端分层

| 层 | 类 | 职责 |
| --- | --- | --- |
| 接入层 | `GameWebSocketHandler` | 解析信封、路由消息、错误回包 |
| 编排层 | `RoomService` | 建房/加入/准备/开局/动作/下一局/结算，房间级锁 |
| 对局层 | `GameTable` | 发牌、摸打、碰杠胡、优先级仲裁、超时 |
| 规则层 | `WinChecker` | 三层判定 + 拆解 + 算番（纯函数，无状态） |
| 视图层 | `ViewMapper` | 领域对象 → 玩家视角视图（隐藏他人手牌） |
| 推送层 | `RoomBroadcaster` | 监听房间事件，逐人推送个性化 `ROOM_STATE` |
| 存储层 | `RoomRepository` | 房间读写抽象，当前内存实现 |

**关键设计**

1. `WinChecker` 是纯函数，不依赖 Spring，可直接单测；牌用 `int 0-33` 编码，算法操作计数数组。
2. `GameTable` 不关心网络，只暴露 `discard / claim / selfKongAn / selfKongBu / selfHu / onTimeout`。
3. 推送永远是「全量视图」而不是增量事件，客户端只做渲染，降低状态不一致风险。
4. 响应阶段有截止时间，`@Scheduled` 每秒扫描超时房间，自动过牌/自动出牌，避免卡桌。
5. 观战者用独立的 `Spectator` 对象挂在 `Room` 上，**不塞进 `players`**：
   `isFull()`、`allReady()`、`nextFreeSeat()`、结算循环全按座位算，
   混进一个无座位的对象就要到处加特判。观战视图靠 `viewerSeat = -1` 自然裁掉手牌与操作。
6. 机器人不做成「一次跑完整局」的循环，而是挂在既有的 `@Scheduled` tick 上：
   一个 tick 只处理当前该动的那一位，动作后把 `Room.botActAt` 推到 `now + think-ms`。
   这样「依次出牌」是**调度结构本身保证**的，不依赖 sleep，也不会占着房间锁空转；
   `BotBrain` 保持纯函数，决策逻辑可以脱离 Spring 单测。

## 五、一次出牌的时序

```
玩家A点击出牌
  → 小程序 socket.send GAME_ACTION(DISCARD, 5W)
  → GameWebSocketHandler 校验登录态/房间
  → RoomService.action 加房间锁
  → GameTable.discard：移除手牌、入弃牌堆、计算 B/C/D 可执行动作
      ├─ 无人可响应 → 下家摸牌，phase = PLAYER_TURN
      └─ 有人可响应 → phase = WAITING_CLAIM，记录 pendingSeats + 截止时间
  → RoomService 发布 RoomUpdatedEvent
  → RoomBroadcaster 为 4 个玩家分别生成视图并推送 ROOM_STATE
  → 小程序 store.setTable → 牌桌重绘（只有自己能看到自己的手牌）
```

响应优先级：**胡 > 杠 > 碰 > 过**；同等优先级按打牌者下家起的座次顺序裁决。

## 六、数据库接入计划

服务器到位后按以下顺序改造，业务逻辑无需改动：

1. 新建表：
   - `mj_user`（玩家账号、昵称、头像）
   - `mj_room`（房间号、房主、规则 JSON、状态、局数、版本号）
   - `mj_room_player`（房间 × 玩家、座位、分数、在线状态）
   - `mj_round`（每局结果、番型、牌谱 JSON，用于回放）
2. 新增 `JpaRoomRepository implements RoomRepository`，用 `@ConditionalOnProperty(mahjong.storage.mode=jdbc)` 切换。
3. `PlayerProfile` 换成 `UserService`（微信 code2session 登录）。
4. 对局中的高频状态仍放内存（`GameTable`），只在「开局 / 每局结算 / 房间状态变更」时落库，避免每出一张牌写一次数据库。
5. 多实例部署时，把房间归属到固定节点（一致性哈希）或引入 Redis 做房间路由。

## 七、并发与一致性

- 同一房间的所有写操作在 `synchronized (room)` 内串行执行，避免两人同时碰牌导致状态覆盖。
- 客户端动作携带的是「牌」，不是「位置」，服务端以自己维护的手牌为准做校验，防作弊。
- 出牌/响应都校验阶段与座位，非法操作直接返回 `ERROR`，不改变状态。
- 断线：`afterConnectionClosed` 标记离线；重连后 `HELLO` 带原 `playerId` 恢复座位与手牌。

## 八、配置项

`server/src/main/resources/application.yml`：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `server.port` | 8080 | 服务端口 |
| `mahjong.game.base-score` | 1 | 底分 |
| `mahjong.game.max-rounds` | 8 | 默认局数 |
| `mahjong.game.action-timeout-seconds` | 15 | 碰杠胡响应超时 |
| `mahjong.game.turn-timeout-seconds` | 20 | 出牌超时 |
| `mahjong.room.idle-timeout-seconds` | 1800 | 空房回收 |
| `mahjong.storage.mode` | memory | 存储模式，接库后改 jdbc |

## 九、开发命令

```bash
# 后端
cd server
mvn test                 # 16 个用例：10 个规则 + 6 个对局状态机
mvn spring-boot:run      # 启动，默认 8080

# 小程序
cd miniprogram
npm install
npm run dev:weapp        # 产出 dist/，用微信开发者工具导入项目根目录
npm run build:weapp      # 生产构建

# 四人联机冒烟（需后端已启动）
cd server
node scripts/ws-smoke.mjs
```
